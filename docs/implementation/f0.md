# F0 — Fundação da aplicação

**Estado:** scaffold implementado com `package-lock.json` versionado; typecheck, lint, testes, build, migração/seed local e CI verificados. Não é deploy nem ambiente pronto para dados reais.

## Decisão prática

Um único projeto Vite com `@cloudflare/vite-plugin` empacota React e Hono/Worker. `src/client/`, `src/worker/` e `src/db/` preservam fronteiras modulares sem criar microserviços. Isto substitui a hipótese de monorepo inicial sugerida em [plano](plan.md) — uma simplificação de F0, não alteração dos módulos de produto.

## Comandos

```bash
npm install
npm run db:migrate:local
npm run db:seed:local
npm run dev
```

A aplicação abre em `http://localhost:5173`; `GET /api/health` devolve apenas estado técnico. `npm run typecheck`, `npm run lint`, `npm test` e `npm run build` executam a validação. `npm run preview` pré-visualiza o Worker compilado.

```bash
npm run cf:typegen
```

Gera tipos quando os bindings evoluírem. `wrangler.jsonc` contém UUID **fictício**, válido apenas como placeholder para D1 local. Não usar o comando deploy até criar uma base real na conta Cloudflare e configurar o ID/bindings/ambientes corretos.

## Segurança

Não há login nem rotas de negócio; a interface é deliberadamente um painel de fundação sem dados de clientes. Os dois tenants da seed são inteiramente fictícios. Não ligar WhatsApp nem usar dados reais nesta fase.

## Migrações

A migração SQL `db/migrations/0001_bootstrap.sql` é a fonte canónica inicial e está alinhada manualmente com `src/db/schema.ts` (Drizzle ORM). **Em aberto:** estabelecer o baseline/snapshots do Drizzle Kit antes de permitir `npm run db:generate` para migrações futuras; sem isso, a ferramenta poderá tentar gerar tabelas já criadas. O comando de aplicação confiável nesta fase é `wrangler d1 migrations apply --local`. Não usar `drizzle-kit push` nem migrações remotas sem revisão.
